# AI司令部(技術名は ai-headquarters)

司令部組織の考え方を、Claude Code のサブエージェント、スキル、Hooks に当てはめた一式です。あなたが「指揮官」として目的と完了条件を示すと、目標と計画の決心、実装、点検、報告が、規律をもって回ります。陸上自衛隊の幕僚活動をモチーフにしていますが、教範どおりではありません。入れてすぐ動き、小さな仕事では重くならない設計です(確かめた環境と、まだ確かめていないことは、第11章にあります)。

> **先に読んでください**
>
> - **Node.js 22 以上が必要です(確かめ方と入れ方は、すぐ下の「まず Node.js を確かめてください」)。** Node.js が無い環境では、統制の仕組み(Hooks)が動かないため、ファイルの書き込み、Bash・PowerShell のコマンドの実行、サブエージェントの起動がすべて止まります(ファイルの読み取りや検索は止まりません)。素通りするより止まるほうを選んでいます。
> - **Hooks は、うっかりした操作を止める安全柵です。意図的なすり抜けまで防ぐセキュリティの仕組みではありません。** Hooks は完全なシェルの解析をしないので、書き方を工夫すれば、保護パスや破壊的コマンドの照合をすり抜けられます。
> - Claude Code 2.1.295 以上が必要です(Hooks の `onFailure` が使える最初の版)。端末で `claude --version` を実行すると、版を確かめられます。
> - このプラグインは、陸上自衛隊の公式な見解や監修を受けたものではありません。言葉は防衛省・陸上自衛隊などの公開資料を参考にしていますが、意味は AI の作業に合わせて使っています。出典は第14章にあります。

この製品がすることは、次の文(指揮の流れ)のとおりです。「指針」は、AI司令部では、あなたが示す「企図」にあたります。実行の監督は、幕僚長(メインセッション)があなたに代わって行い、あなたは報告を受けます。

> 指揮官の指針を受けて、幕僚が任務を分析し、達成すべき目標を明らかにする。指揮官がこれを決心したのち、幕僚が幕僚活動を実施して最良の行動方針を案出し、指揮官が決心する。命令を起案して発出し、部隊がこれを実行して任務を達成する。指揮官は実行を監督し、報告を受けて任務の達成を確かめる。

## まず Node.js を確かめてください

**AI司令部は、Node.js(ノード・ジェイエス)が入っていないと使えません。** 安全のための確認の仕組み(Hooks)を Node.js で動かしているためです。Node.js が無いと、確認ができないので、安全のために、ファイルの書き込み、コマンドの実行、サブエージェントの起動がすべて止まります。導入の前に、次の手順で確かめてください。

### 入っているかの確かめ方

1. 端末を開きます。Windows は「PowerShell」(スタートメニューで「PowerShell」と検索)、Mac は「ターミナル」(Spotlight で「ターミナル」と検索)です。
2. 次のように入力して、Enter を押します。

```text
node --version
```

3. 結果を見ます。
   - `v22.12.0` や `v24.11.1` のように、`v` のあとの最初の数字が **22 以上** なら、そのまま使えます。
   - 数字が 22 より小さいときは、古い版です。下の手順で入れ直してください。
   - 「認識されません」「command not found」などと出たときは、入っていません。下の手順で入れてください。

### 入れ方

1. Node.js の公式サイト(<https://nodejs.org/ja>)を開き、「LTS」(長期サポート版)と書かれた版のインストーラーをダウンロードします。
2. ダウンロードしたファイルを開き、画面の案内に従って入れます。設定は、最初から選ばれているままで構いません。
3. 開いていた端末と Claude Code を、いったんすべて閉じてから、開き直します(開き直さないと、入れた Node.js が見つかりません)。
4. もう一度 `node --version` で確かめます。

Windows で、コマンドで入れたい場合は、PowerShell で `winget install OpenJS.NodeJS.LTS` でも入れられます。

導入したあとに、書き込みやコマンドが理由も分からず止まるときも、まず Node.js が入っているかを確かめてください。

## はじめの5手順

1. Node.js が入っていることを確かめ(上の「まず Node.js を確かめてください」)、導入します(第5章)。デスクトップアプリで入れると、ユーザー全体(すべてのプロジェクト)に入ります。プロジェクト単位で入れたいときは、端末で入れます。特定のプロジェクトで止めたいときは、そのプロジェクトの `.claude/settings.local.json` の `"enabledPlugins"` に `"ai-headquarters@ai-headquarters": false` と書きます(第5章の「デスクトップアプリだけを使っている場合」の「入る範囲」)。
2. Claude Code で、新しいセッションを開きます。
3. 目的、完了条件、制約を添えて依頼します。進め方の程度(実行だけ、簡易、完全)を最初に書けば、そのとおりに進みます。書かなければ、推奨の程度と見込みが示されます。
4. 目標が示されたら読み、よければ「承認」とだけ入力するか、直す点を書きます。続けて計画が示されたら、同じように決心します(実行だけでは、どちらも要りません)。
5. 結果、未解決、処置事項の一覧、見込みとの差の報告を受けます。直したい処置事項があれば、番号で伝えます。

## 1. 組織の考え方

指揮官(あなた)が企図を示し、目標と計画を決心し、最終判断をします。メインセッションが幕僚長になり、あなたが決心した範囲で、各部と部隊に任務を与えます。

**幕僚**は、指揮官を補佐する役です。幕僚長(メインセッション)のもとで、第2部(intel)が調べ、第3部(plans)が案を作り、監察(inspector)が点検します。この3体は書き込みません。**隷下部隊**は、命令の範囲で実際に手を動かす部隊で、AI司令部では実装を担う unit です。

| 役職 | 役割 | 実体 | 権限 |
| --- | --- | --- | --- |
| 指揮官 | 企図を示し、目標と計画を決心し、最終判断する | あなた | 全権 |
| 幕僚長 | 任務分析、計画、命令、監督、報告の取りまとめ | メインセッション | 指揮官の決心の範囲で全ツール |
| 第2部 | 調べて、事実と根拠だけを報告する | サブエージェント `intel` | 読み取りと検索のみ |
| 第3部 | 完全の程度で、行動方針を2〜3案作る | サブエージェント `plans` | 読み取りのみ |
| 隷下部隊 | 命令の範囲で実装する | サブエージェント `unit` | 読み書きとコマンド実行 |
| 監察 | 成果物の独立した点検と、案の弱点の検討 | サブエージェント `inspector` | 読み取りとテスト実行 |

### 製品の核

1. **幕僚役は書き込まない。** intel、plans、inspector は、書き込む道具を持たず、Hooks でも止めます。点検は作った本人以外が行います。
2. **決心は指揮官だけが行う。** 目標と計画の「承認」が無ければ、unit は動きません(Hooks で止めます)。
3. **戻せない操作と外に出す操作は、指揮官が決める。** 破壊的なコマンド、保護パスへの書き込み、コミット、push、公開、デプロイ、遠隔への転送は、サブエージェントでは止め、メインセッションには確認を出します。

そのほか、**小さな仕事は単独で片付ける**ことを大事にしています。誤字の直しのような作業では、サブエージェントを起動せず、作戦記録も作りません。**点検は作った本人以外が行う**ので、unit が作ったものは inspector が確かめ、inspector は指摘だけを返して、自分では直しません。

## 2. 使い方

### 作戦を始める

ふだんどおりに依頼します。セッションの開始時に、AI司令部の進め方(スキル `mission-analysis`)を読み込むよう案内が入るので、`/` のコマンドは要りません。はっきり始めたいときは、`/ai-headquarters:mission` に依頼を添えて送ります(Claude が勝手に始めることはありません)。

```text
/ai-headquarters:mission 簡易 ログイン画面の初回表示を速くしたい。完了条件は…、触ってはいけないものは…
```

**企図**は、あなたが達成したいことと、その理由です。手順ではなく、目的、完了条件、制約の3つを書くと、任務分析がぶれません。書き方の例は、GitHub のリポジトリ(<https://github.com/namakemono-tech/ai-headquarters>)の `templates/CLAUDE.example.md` にあります(使う場合は、自分の CLAUDE.md に写します)。プラグインとして入れても、雛形はあなたのプロジェクトの中には置かれません。

### 進め方の程度

どこまで計画するかは、あなたが決めます。依頼の最初に、程度の語を書きます。

| 程度 | 流れ | 編成 |
| --- | --- | --- |
| 実行だけ | 依頼 → 幕僚長が実行 → 報告 | 幕僚長だけ。作戦記録は作らない |
| 簡易 | 短い任務分析 → 目標の決心 → 計画(1案) → 計画の決心 → unit → 点検 → 報告 | unit、inspector |
| 完全 | 任務分析 → 目標の決心 → 案を比べる → 計画の決心 → unit(中間報告つき) → 点検 → 報告 | 4体 |

- 程度を書けば、それに従い、伺いません。「実行だけ」と書いたときは、進め方のスキルも読み込まずに、そのまま実行します。
- 書かなければ、最初の応答の冒頭に、推奨の程度と、3つの程度の見込み(時間、使用量)が3行で示されます。推奨が「実行だけ」なら、そのまま始めます。「簡易」か「完全」なら、同じ応答で、短い任務分析と目標の案まで示して伺います。「承認」だけの答えは、推奨のとおりです。
- 戻せない操作が要る、変更が見込みより広がった、目標の読みが分かれる、保護パスや登録に触る、と分かったときは、一段だけ重くすることを、理由と見込みを添えて1回伺われます。
- 見込みは、前の作戦の実測(`.ai-headquarters/estimates.md`)があれば、その数字から出されます。無ければ「実測前」の目安です。

### AI司令部の思考過程

決まりの正本は `skills/mission-analysis/SKILL.md` です。細かい手順は決めず、幕僚長が判断の物差し(目標、統一、保全、経済、簡明、集中、主動、機動、工夫と、適時性、先行性、並行性、完全性)で決め、決めたことを報告します。

#### 2つの関門と、決心の入力のしかた

- **決心**は、幕僚が示した案を、あなたが決めることです。簡易と完全では、**目標の決心**と**計画の決心**の2回です。
- 目標の決心では、企図(原文のまま)、必成目標(原則1つ)と望成目標、点検の物差し(合否を決める項目)、読みが分かれる所と推奨の読み、戦力の見込みと配分(重点、そのほか、予備に割った数字)が示されます。
- 計画の決心では、行動方針の要旨、手順(誰が、何を)、変更してよい範囲、重点、戻せない操作(無ければ「無い」)、点検のしかた、戦力の配分が示されます。計画の前に、変えるファイルに関わる既存のテストも探され、範囲に入れるかが決まります。
- 示された案でよければ、**「承認」とだけ入力**します。前後の空白と、末尾の「。」「!」を除いて、「承認」と完全に一致したときだけ承認と見なします(「承認します」「OK」「続けて」は承認になりません)。
- 直したいときは、直す点を書きます。反映した内容が示されます。計画の決心では、反映のあとに、改めて「承認」が求められます。
- 目標の決心を省けるのは、あなたが企図で目標をすべて示し、幕僚が補ったものも改めたものも無いときだけです。省いたときは、理由が報告と作戦記録に書かれます。
- 目標の決心だけでは、unit は起動できません。

#### 伺われることと、一覧で示されること

- あなたに1つずつ伺うのは、次のどれかに当たるものだけです。(ア)決心したもの(目標、方針、あなたが示した制約)を変える。(イ)戻せない、または作戦の外に出る(前からあった物の削除、公開、送信、コミット、push、デプロイ)。(ウ)推奨を1つに絞れない(選び方で、必成目標の達成か、物差しの合否が変わる)。
- それ以外の細部は**処置事項**です。幕僚長が決めて先へ進み、次の報告に一覧(1件1行。決めた内容と理由)で示します。直したいものがあれば、番号と直し方だけを書きます。
- 伺うときは、推奨と理由に、選択肢ごとの見込みが添えられます。
- **速報事項**(戻せない操作の前、範囲の外への変更、使用量や時間が見込みを大きく超えそうなとき)は、起きる前に知らされます。

#### 実行、監督、点検、報告

- 簡易と完全では、幕僚長は成果物を自分で書かず、**命令書**(サブエージェントへの依頼書)で unit に命じます。unit は同時に1体で、命令書の【変更してよいファイル】の中だけを書けます。
- 幕僚長は、unit の報告を受けるたびに、頼んだ物か、命令に無い作り込みが無いかを見ます(監督)。外れは是正を命じ、同じ所で2回目なら、あなたに上げます。
- inspector が最低1回点検します。合否は物差しだけで決めます。物差しの外の指摘は不合格にせず、重いものはすぐ知らされ、ほかは処置事項になります。同じ所で2回続けて不合格なら、直しを命じず、残った指摘を示して伺われます。
- Hooks が知らせる数字(作業の時間、起動の回数と設定の線)を、幕僚長が配分と照らします。配分の8割で、切り上げか縮小の案が1行で知らされます。
- 最終報告は、結果、目標ごとの達成、未解決、処置事項の一覧、見込みとの差(時間、使用量)です。終えると、次の見込みに使う実測が `.ai-headquarters/estimates.md` に1行足されます。
- Hooks か権限に止められたサブエージェントは、別の手段で同じことを試さず、未解決として上げます。

#### 作戦記録

簡易と完全では、任務分析の時に**作戦記録**(作戦ごとの記録。`.ai-headquarters/operations/OP-001.md` など)が作られます。見出しは9つです(企図、目標、方針、承認、いま、任務の記録、処置事項、片付け、結果)。新しいセッションは「いま」までを読めば続けられます。作業フォルダ(作業対象のプロジェクト)の外にファイルやフォルダを作るときは、計画の決心で場所が名指しされ、「片付け」に、場所、何のためか、いつ消すかが1行ずつ書かれます。作戦を閉じるときに、この一覧が示され、消すか残すかを伺われます(Hooks では止めません)。承認は「目標」と「方針」の2つの節に結び付くので、その外(手順の細部、実測、任務の記録)は、承認を外さずに書き換えられます。

## 3. 各ファイルの役割

| ファイル | 役割 |
| --- | --- |
| `.claude-plugin/plugin.json` | プラグインの名前(`ai-headquarters`)、画面に出る名前(`AI司令部`)、版 |
| `.claude-plugin/marketplace.json` | 配布用の一覧(画面に出る名前は、こちらの値が優先されるため、plugin.json と同じ値を書いています) |
| `agents/intel.md` | 第2部。調べて、事実と根拠を報告する。読み取りと検索のみ(既定は haiku) |
| `agents/plans.md` | 第3部。完全の程度で、行動方針を2〜3案作る。読み取りのみ(opus) |
| `agents/unit.md` | 隷下部隊。命令書の範囲で実装する(sonnet) |
| `agents/inspector.md` | 監察。成果物の点検と、案の弱点の検討。指摘だけを返す(sonnet) |
| `skills/mission/SKILL.md` | `/ai-headquarters:mission`。進め方のスキルを読み込んで始める入口 |
| `skills/mission-analysis/SKILL.md` | 決まりの正本(指揮の流れ、核、判断の物差し、進め方の程度、2つの関門、伺いの基準、命令と報告の型、作戦記録の雛形) |
| `hooks/hooks.json` | Hooks の登録 |
| `hooks/guard.js` | 役ごとの制限、保護パス、破壊的なコマンド、外に出す操作とコミット、unit の範囲、承認の関門(指紋の照合)、承認の引き継ぎ、unit は同時に1体、起動の数え上げ、設定の線の知らせ、作戦記録・設定・状態の保護 |
| `hooks/approval.js` | 指揮官の「承認」を、目標の決心と計画の決心に分けて記録する。計画の決心では、「目標」と「方針」の節の指紋を取り、作戦記録の「承認」の節に1行書き足す。作戦記録への「引き継ぎ待ち」「受け継ぎの申し出」の書き込みを記録する |
| `hooks/clock.js` | 時計。作戦中に、時刻、作業の時間、起動の回数と設定の線を、メインセッションに知らせる |
| `hooks/session-start.js` | 進め方のスキルを読み込む案内を、セッション開始時に入れる。設定ファイルに役ごとのモデルがあれば、その1行も。続いている作戦があれば、引き継ぎの案内も |
| `templates/CLAUDE.example.md` | 企図の書き方の例(任意) |
| `templates/operations-log.md` | 作戦記録の雛形(見出し9つ) |
| `templates/config.json` | 設定ファイルの例 |
| `LICENSE` | ライセンス(MIT) |
| `tests/`、`scripts/run-tests.js`、`package.json`、`.github/` | Hooks、エージェント、スキルの動きを、Mac と Windows で自動で確かめるためのもの。AI司令部を使うときには要りません |

Hooks のスクリプトは、シェルや Python に依存せず、Node.js だけで動く単体のファイルです。登録は、シェルを経由しない形(`"command": "node"` と `"args"`)で書いてあるので、Windows の Git Bash でも PowerShell でも同じに動きます。

### 命令書と報告の型

サブエージェントは会話の文脈を持たずに起動するため、命令書は単体で読める形にします。見出しは【企図】【任務】【状況】【変更してよいファイル】(unit だけ)【制約と完了条件】【報告してほしいこと】です。【変更してよいファイル】は、見出しの行には何も書かず、次の行から1行に1つ、プロジェクトの最上位からの相対パスで書きます。報告は【結論】【根拠】【変更したファイル】【未解決】で受け、inspector は【結論】の1行目に合格か不合格かを書きます。

## 4. Hooks が確認して止めること

Hooks は自動でコマンドを実行します。何を確認して何を止めるかを、すべて書きます。

### 止め方の2種類

- **サブエージェント:止めます**(拒否)。
- **メインセッション(あなたとの対話):確認を出します**(あなたが判断します)。あなたが自分で頼んだ操作(`rm -rf node_modules` など)まで止まると、許す道が無くなるためです。
- 例外として、次の3つは、メインセッションでも**止めます**。承認の記録や設定、作戦の証拠を、Claude が書き換えたり消したりできないようにするためです。
  - `.ai-headquarters/config.json` への書き込み
  - `.ai-headquarters/state/` の中のファイルへの書き込み
  - 作戦記録の削除と、丸ごとの上書き(Write)

メインセッションかどうかは、Hooks の入力に `agent_id` があるかで見分けます。agent teams の仲間のセッションも `agent_id` を持つので、サブエージェントとして扱います。

### 役ごとの制限

実行中のエージェントの種類(`agent_type`)を見て、次のとおり制限します。プラグイン同梱のエージェントでは、定義ファイルに書いた Hooks が無視されるため、プラグイン全体の Hooks で行います。

| 役 | 制限 |
| --- | --- |
| intel、plans | 書き込み系のツール(Edit、Write など)と、Bash・PowerShell の実行を止める |
| inspector | 書き込み系のツールを止める。Bash・PowerShell は**許可リスト**に合うものだけを通す(下の表) |
| unit | 書き込みは、命令書の【変更してよいファイル】の範囲だけ(下の「unit の範囲」) |
| intel、plans、unit、inspector 共通 | ほかのサブエージェントを起動することを拒否する |
| 種類を判別できないもの(組み込み、他のプラグインのエージェント) | 役ごとの制限はかけない。保護パス、破壊的コマンド、作戦記録・設定・状態の保護だけを当てる(他のプラグインを壊さないため) |

**inspector の Bash・PowerShell の許可リスト**

コマンドの中身から書き込みを見抜く方式は漏れが出るため、「通してよいものだけを通す」方式にしています。

| 種類 | 通すもの |
| --- | --- |
| テスト | 既定で `npm test`、`pnpm test`、`yarn test`、`node --test`、`pytest`、`go test`、`cargo test`。`-` で始まらない引数(ファイルのパスやテスト名)は付けてよい。`-` で始まるオプションは、設定ファイルに書いたものだけ通す。プロジェクト固有のテストコマンドも設定ファイルで足せる |
| 読み取り専用の git | `git diff`(`--stat`、`--name-only`、`--name-status`、`--cached`、`--staged`)、`git status`(`-s`、`--short`、`--porcelain`)、`git log`(`--oneline`、`-n`、`--stat`、`--format`)、`git show`(`--stat`、`--name-only`)、`git ls-files`(`--cached`、`--deleted`、`--modified`、`--others`、`--exclude-standard`)。`git -C <フォルダ>` を前に付けてもよい |
| 読み取りだけの ls | `ls`(`-l`、`-a`、`-la`、`-al`、`-1`、`-R`)と、パスの引数 |
| 出力の絞り込み | `|` のあとの `head`、`tail`、`grep`、`wc`(`tail -f` は止める) |

- 上のコマンドは、`&&` と `;` でつなげます。つないだ部分のそれぞれが、上の表に合わなければなりません。
- 許可リストどおりの `git diff`、`git log`、`git show` は、Hooks が `--no-ext-diff --no-textconv` を付け足したうえで `allow` を返し、通常の確認を飛ばして実行します(外部のプログラムが動くのを防ぐため)。
- `git` の直後(`-C <フォルダ>` を付けたときはその後)には、上の5つのサブコマンドが来なければなりません。`-c`、`--git-dir`、`--work-tree`、`--exec-path` など、間に置くほかのオプションは止めます。`-C` のフォルダが無いとき、ネットワークのパスのときも止めます。
- `||`、`&`、`>`、`>>`、`<`、`$`、`(`、`)`、`{`、`}`、バッククォート、改行を含むコマンドは止めます(`2>&1` も止まります)。引用符の中にも当てるので、`--format="%h|%s"` も止まります。
- 読み取り系のコマンドでも、オプション次第で、ファイルを書いたり(`--output`)、外部のプログラムを動かしたり(`--ext-diff`、`--textconv`、`-c`)できるため、許すオプションを限っています。

### 保護パス

書き込みの前にパスを確認します。`.env` などの秘密のファイルは、シェルでの読み取り(`cat` など)も確認の対象にします。**Read ツールでの読み取りは Hooks を通らないため、止まりません**(Read、Grep、Glob は Hooks の対象外です)。表の「止める」は、第4章の止め方に従います(メインセッションには確認、サブエージェントには拒否)。文字列の部分一致は使いません(`process.env` や `.env.example` まで止めないためです)。

| 保護するもの | 照合の単位 | シェルでの読み取り(`cat` など) |
| --- | --- | --- |
| `.env`、`.env.*`(ただし `.env.example`、`.env.sample`、`.env.template` は除く) | ファイル名 | 止める |
| `*.pem`、`*.key`、`*.p12`、`*.pfx`、`*.jks`、`*.keystore`、`id_rsa*`、`id_ed25519*`、`.npmrc`、`.netrc`、`secrets.toml` | ファイル名 | 止める |
| `credentials`、`credentials.json`、`credentials.yml`、`credentials.yaml`、`secrets.json`、`secrets.yml`、`secrets.yaml`、`.secrets` | ファイル名(`credentialsService.ts` のような普通のソースは止めません) | 止める |
| 設定ファイルで追加したパス | 設定ファイルの書き方による | 止める |
| `.ai-headquarters/config.json`、`.ai-headquarters/state/` の中 | プロジェクトの最上位からの相対パス | 通す |
| `.claude/settings.json`、`.claude/settings.local.json`、`.claude/hooks/ai-headquarters/` の中 | プロジェクトの最上位からの相対パス | 通す |

最後の2行は、書き込みだけを止めます。読み取りは通します。

パスは、照合の前に、プロジェクトの最上位からの相対パスに直し、区切りを `/` にそろえます。Windows と Mac では、大文字・小文字の違いを無視します(Linux は区別します)。操作の対象が、保護された場所の上位のフォルダ(`.ai-headquarters/`、`.claude/` など)のときも、一致と見なします。`mv .ai-headquarters x` のように、フォルダごと動かして保護をすり抜けるのを防ぐためです。

**追加と除外(設定ファイル)**: 書き方は `.gitignore` に近い形です。

- `/` を含まない項目(例:`*.secret`)は、ファイル名として、どのフォルダでも当てます。
- `/` を含む項目は、プロジェクトの最上位からの相対パスとして当てます。`**` で何段のフォルダにも当てられます。
- 末尾が `/` の項目は、フォルダとして扱い、中のすべてのファイルに当てます。
- 設定ファイル、状態ファイル、作戦記録の保護は、「除外」では外せません。

### 破壊的なコマンド

Bash と PowerShell の実行前に、次のものを照合します(メインセッションには確認、サブエージェントには拒否)。

- `rm -r`、`rm -rf`(パスを問いません。`rm -fr`、`rm -R`、`rm --recursive` も同じ扱い)
- `git push --force`、`git push -f`、`git push --force-with-lease`
- `git push origin +main`(`+` を付けた強制)、`git push --force-if-includes`
- `git reset --hard`、`git clean -f`、`git checkout -- .`、`git checkout .`、`git restore .`、`git branch -D`(`git branch --delete --force` も同じ扱い)
- `git stash -u`、`--include-untracked`、`-a`、`--all`(未追跡の設定や `.env` をまとめて退避するため)
- `Remove-Item -Recurse`(別名の `rm`、`del`、`ri`、`rd`、`rmdir` を含む)、`rd /s`、`del /s`
- `format`、PowerShell の `Format-Volume`(コマンド名として使った場合)、`find ... -delete`

コマンドを `&&`、`||`、`;`、`|`、`&`、`(`、`$(`、バッククォート、改行で区切り、各部分の先頭の語と引数で照合します。`cmd /c`、`bash -c`、`sh -c`、`pwsh -c`、`powershell -Command`、`sudo`、`env`、`xargs` は「包み」として、後ろのコマンドを取り出して照合し直します。`git log --format=...` や `npm run format` のように、語の一部に含まれるだけのものは止めません。1つのファイルの削除(`rm a.txt`、`git rm a.txt`)は、この一覧に入りません。Claude Code の権限の確認に任せます。

### 外に出す操作とコミット

成果を外に出す操作とコミットも、戻せない操作として、サブエージェントでは止め、メインセッションには確認を出します(bypassPermissions では拒否)。コミットするか、外に出すかは、報告を受けたあなたが決めます。

- `git commit`、`git push`(`git -C <フォルダ>` を付けたものを含む)
- `npm`、`pnpm`、`yarn`、`cargo`、`bun` の `publish`(`yarn npm publish` を含む)
- `gh release` の `create`、`upload`、`edit`、`delete`
- `docker push`、`podman push`
- `vercel`(サブコマンドなし、`deploy`、`--prod`)、`netlify deploy`、`firebase deploy`、`wrangler deploy`(`wrangler publish` を含む)
- `kubectl apply`、`terraform apply`、`tofu apply`
- `ssh`、`scp`、`sftp`、遠くのホストを指す `rsync`(`host:path` の形の引数)
- `npx`、`pnpx`、`bunx`、`pnpm dlx`、`pnpm exec`、`npm exec`、`yarn dlx`、`yarn exec` を通したものも、流す道具の名前で照合します

### 作戦記録、設定、状態の保護

- 作戦記録(`.ai-headquarters/operations/`)の削除と、Write での丸ごとの上書きを止めます(メインセッションでも)。部分的な更新(Edit)は通します。削除と移動のコマンド(`rm`、`del`、`Remove-Item`、`mv`、`move`、`Move-Item`)の引数に `.ai-headquarters/operations/` があれば止めます。
- 既存の作戦記録を、シェルで丸ごと上書きすることも拒否します(メインセッションでも)。`>` でのリダイレクト、`Set-Content`、`cp`、`mv`、`sed -i`、`tee`(`-a` なし)が対象です。追記(`>>`、`Add-Content`、`tee -a`)は通します。
- 作戦記録があるとき、作戦記録を巻き込みうる `git clean -fdx`(`-d`、`-x`)は、メインセッションでも拒否します。
- サブエージェントによる `.ai-headquarters/` への書き込みを止めます。
- 設定ファイルと状態ファイルへの書き込みを止めます(メインセッションでも)。

### Claude Code の設定(`.claude/`)の保護

`.claude/settings.json`、`.claude/settings.local.json`、`.claude/hooks/ai-headquarters/` と、その親のフォルダ(`.claude/`、`.claude/hooks/`)を対象にした操作も、一致と見なします(メインセッションには確認、サブエージェントには拒否)。対象の操作は、削除、移動、名前の変更、`git checkout`、`git restore`、`cp`・`rsync`・`Copy-Item` などの書き込み先です。`git restore --staged` のようにワークツリーを変えないものは通します。

### プラグインと MCP のコマンド

プラグインと MCP の状態を変えるコマンドは、サブエージェントでは止め、メインセッションには確認を出します。作戦の外でも、ほかのプラグインのエージェントにも当てます。入れたものの Hooks や MCP サーバーは利用者の権限で動き、AI司令部自身を外す(`disable`、`uninstall`)こともできるためです。

- `claude plugin`(別名 `claude plugins`)のサブコマンドのうち、`list`、`details`、`validate`、`help` 以外のすべて(`install`、`uninstall`、`enable`、`disable`、`update` など)。`marketplace` は `list`、`help` 以外
- `claude mcp` のサブコマンドのうち、`list`、`get`、`help` 以外のすべて(`add`、`add-json`、`remove` など)
- `claude` に `--plugin-dir`、`--mcp-config`、`--dangerously-skip-permissions` を付けた入れ子の起動

### スキル、エージェント、MCP の登録への書き込み

プロジェクトの `.claude/skills/`、`.claude/agents/`、`.mcp.json` への書き込みは、AI司令部の4体だけを守る相手にして、次のとおり扱います。

- unit: 命令書の【変更してよいファイル】にはっきり書かれているときだけ書けます。`.claude/skills/**`、`.claude/skills/a/SKILL.md`、`.mcp.json` のように、そのパスを書いたときです。`**`、`.claude/**`、`*.json` のような広いグロブにたまたま含まれるだけでは、書けません。
- intel、plans、inspector: 止めます(読み取り専用の役です)。
- 4体以外のサブエージェントとメインセッションは止めず、確認も出しません。AI司令部と関係のない普段の作業を止めないためです。
- シェルのコマンドで、この3つを書き換えるもの(削除、移動、コピーの書き込み先、リダイレクトなど)は、4体では止めます。unit が書くときは、Edit か Write を使います。

### unit の範囲

unit を起動するときに、命令書の【変更してよいファイル】を記録します。unit が Edit・Write を使うたびに、その範囲と照合し、範囲外なら止めます。範囲の中なら、新しいファイルを作ってかまいません。欄が無いとき、読み取れないときは、unit の起動を止め、欄の書き方を理由文でメインセッションに伝えます。シェル(Bash・PowerShell)には範囲の照合をかけません。かけると、テストやビルドまで止まってしまうためです。

### 承認の関門

あなたの「承認」の発言を、目標の決心と計画の決心に分けて記録し、計画の決心が無い間は unit の起動を止めます。記録は `.ai-headquarters/state/approvals.jsonl` に1行ずつ足します。

- 計画の決心として記録するのは、同じセッションの同じ作戦で目標の決心がすでに記録されているとき、作戦記録の「目標の決心: 」の行が「修正」か「省略」で始まるとき、受け継ぎの申し出のあと、承認を持つセッションの2回目からの「承認」(記録し直し)のときです。迷ったら目標の決心の側に倒します。
- 計画の決心では、作戦記録の「## 目標」と「## 方針」の2つの節から**指紋**(中身から計算した値)を取って記録し、作戦記録の「## 承認」の節に「計画の決心: 承認 日時(指紋 …)」の1行を書き足します。「## 方針」が無い、空、または「未作成」のときは、計画の決心として記録しません。
- unit を起動するときに、いまの作戦記録の2つの指紋と照らし、違えば止めて、書き換えた点を示して「承認」を受け直すよう伝えます。本文の前後の空行、行末の空白、改行の種類の違いでは変わりません。2つの節の外(「いま」「任務の記録」「処置事項」「結果」)を書き換えても、承認は外れません。
- 作戦記録が1つも無いときと、最新の作戦記録が閉じている(「## 結果」が「未完了」でない)ときに「承認」と書かれても、記録しません。閉じた作戦の承認では、unit も起動できません。新しい仕事は、次の番号の作戦記録で始めます。

### 承認の引き継ぎ

セッションを替えると言ったときと、文脈が足りなくなりそうなときは、メインセッションが作戦記録の「## いま」に「引き継ぎ待ち: 」の行を書きます。そのあと別のセッションが続けると、目標と方針が変わっていなければ(指紋が同じなら)、承認を引き継ぎます。「承認」の入れ直しは要りません。引き継ぎを書かないままセッションが替わったときは、新しいセッションが方針と任務の要点を示し、「受け継ぎの申し出: 」を書いてから、あなたの「承認」を1回受けます。どちらでも、unit を起動できるのは、承認を持つ1つのセッションだけです。`claude --continue` で続けた会話は、同じセッションです。

### 知らせ(時計と設定の線)

作戦中(最新の作戦記録の「## 結果」が「未完了」のあいだ)は、あなたの発言のたびと4体が戻るたびに、時刻を `.ai-headquarters/state/clock.jsonl` に記録し、メインセッションに1行で知らせます(例:「時計: 2026-11-26 14:32。OP-003 は開始から 72分。作業 48分(線 60分)、起動 6回(線 12回)。」)。モデルは今の時刻を知らないので、時間の数字は、この知らせから取らせます。

作業の時間か起動の回数が、設定ファイルの線(既定は 60分と12回)を超えると、作戦ごと、線ごとに1回だけ、あなたの画面に「止めずに続けています。続けるか、切り上げるかは、幕僚長の報告を見て決めてください」という知らせを出します。知らせるだけで、止めません。

### unit は同時に1体

unit の「予約」を、すでにあれば失敗する作り方で書き、書けなければ起動を止めます。同じ応答で2体の unit が呼ばれても、片方だけが通ります。予約は、unit の起動の知らせ(SubagentStart)か、unit が最初に書き込むかコマンドを使ったときに、実行中の記録に切り替えます。切り替わらない予約は2分で、30分のあいだ書き込みもコマンドもしていない実行中の記録は、無効と見なします。中断や異常終了で、unit が二度と起動できなくなるのを防ぐためです。

**unit を起動できないと言われたとき**:セッションが異常に終わったあと、別のセッションで unit を起動しようとすると、「別のセッションの unit が実行中です」と止まります。長くて30分です。対処は2つです。

1. 30分待ちます。
2. 動いている unit がもう無いと分かっているなら、あなたが自分で `.ai-headquarters/state/unit-lock.json` を消します(Claude には消せません。状態ファイルへの書き込みは、Hooks が止めています)。

### Hooks が動かなかったとき

- `hooks/guard.js` の **PreToolUse の登録**には、スクリプトが起動できない、異常終了した、時間切れになったときも、元の操作を**止める側に倒す** `"onFailure": "block"` を付けてあります。
- `guard.js` の SubagentStart の登録と、承認の記録、時計、セッション開始の案内には付けていません(動かないときに、あなたの発言や報告の受け渡しまで止めないため)。10秒で時間切れになり、そのまま先へ進みます。

### 権限モードごとの確認の振る舞い

メインセッションへの「確認」は、Claude Code の権限モードで変わります。

| 権限モード | メインセッションへの確認の出方 |
| --- | --- |
| default、acceptEdits | 確認が出る |
| auto | 確認が出る(自動の判定役は使われない) |
| bypassPermissions | Hooks は確認の代わりに拒否を返す(確認の画面が出ないため) |
| dontAsk、`-p` での実行 | Hooks の確認は、拒否になる。ただし、Claude Code 自身が重要な場所の削除(rm -rf など)として扱うものは、確認の画面が出ることがある(実機で観測) |

ほかのプラグインの `PermissionRequest` の Hooks が、この確認に自動で答えてしまう場合があります。

## 5. 導入

Claude Code を、Claude のデスクトップアプリ(「Code」タブ)だけで使っていて、端末(ターミナル)では使っていない場合は、下の「デスクトップアプリだけを使っている場合」の手順で、画面の操作だけで入れられます。

### 端末で入れる場合

プロジェクト単位(`--scope project`)で入れるのを標準とします。次のコマンドは、**端末(ターミナル)で**、対象のプロジェクトの最上位で実行します。

端末は、開いた直後はホームのフォルダにいます。先に、`cd` でプロジェクトのフォルダへ移ってください。次は、プロジェクトが `D:\projects\myproject` にある場合の例です(パスは、Windows ではエクスプローラーのアドレス欄から、Mac では Finder でフォルダを端末へドラッグすると得られます)。

```text
cd "D:\projects\myproject"
```

移ったら、`pwd`(Windows の PowerShell でも使えます)で、今いるフォルダがプロジェクトのフォルダであることを確かめてから、次のコマンドを実行します。

GitHub で公開しているものを、次の2つのコマンドで入れます。

```text
claude plugin marketplace add namakemono-tech/ai-headquarters --scope project
claude plugin install ai-headquarters@ai-headquarters --scope project
```

GitHub のリポジトリを丸ごとダウンロード済みの場合は、1つ目のコマンドの `namakemono-tech/ai-headquarters` を、そのフォルダ(`.claude-plugin/` があるフォルダ)のパスに置き換えてください。2つ目は同じです。この場合、更新するときは、先にそのフォルダの中身を新しい版に入れ替えてから、下の「更新のしかた」を行います。

**SSH の鍵を GitHub に設定していない場合**:1つ目のコマンドは、まず SSH で取得を試し、失敗すると自動で HTTPS で取り直します(「SSH clone failed, retrying with HTTPS」と表示されます)。公開しているリポジトリなので、HTTPS での取得にログインは要りません。それでもうまくいかない場合は、1つ目のコマンドを、HTTPS の URL を指定する次の形に置き換えてください。2つ目は同じです。

```text
claude plugin marketplace add https://github.com/namakemono-tech/ai-headquarters.git --scope project
```

**入ったことの確かめ方**:Claude Code で、そのプロジェクトの新しいセッションを開き、`/agents` で `ai-headquarters:intel`、`ai-headquarters:plans`、`ai-headquarters:unit`、`ai-headquarters:inspector` の4体が出ること、`/` を入力したときの一覧に `/ai-headquarters:mission` が出ることを確かめます。

**利用者全体(`--scope user`)に入れた場合に起きること**:

- すべてのプロジェクトで Hooks が動きます。保護パス、破壊的コマンド、外に出す操作とコミットの確認、サブエージェントの制限がかかります。
- すべてのプロジェクトで、セッション開始時に、進め方のスキルを読み込む案内が入ります。
- 全体の CLAUDE.md と衝突しやすくなります(第8章)。

### デスクトップアプリだけを使っている場合

Claude Code を、Claude のデスクトップアプリの「Code」タブだけで使っている場合も、端末(ターミナル)を使わずに、画面の操作だけで入れられます。次の手順は、Windows のデスクトップアプリの日本語の画面で確かめたものです。画面の表記は、アプリの版や表示の言語で変わることがあります。

**入れ方**

1. 左のメニューの「プラグイン」を開きます。
2. 右上の「追加」の ▼ を押し、「マーケットプレイスを追加」を選びます。
3. 「リポジトリから追加」を選びます。「URL」の欄に `namakemono-tech/ai-headquarters` と入力し、「同期」を押します。欄の下に、手元のリポジトリの候補が出ることがありますが、それは選びません。
4. 同期すると、そのまま画面に AI司令部が出ます。「作成者: ナマケモノテック」と説明文が並び、右に「このコンピューターに追加」があります。
5. 「このコンピューターに追加」を押すと、「プラグイン「AI司令部」には、コードを実行するコンポーネントが含まれている可能性があります」という確認が出ます。「お使いのコンピューターで実行されるセッションでは、許可を求めずにそのコンピューター上でコードを実行する可能性があります。」「信頼できる人が作成したプラグインのみをオンにしてください。」と書かれ、「キャンセル」と「続ける」があります。AI司令部は、統制のために Hooks で Node.js のスクリプトを動かすので、この確認が出ます。
6. 「続ける」を押すと、「追加済み」と版の番号(v0.6.0 など)が出ます。これで入っています。

同じマーケットプレイスがすでに追加されている場合も、同じ手順で、同期のあとに AI司令部が出て、入れられます。

**入ったことの確かめ方**

- 設定の「プラグイン」の一覧の「その他のプラグイン」に、「AI司令部」が「ローカルにインストール済み」「提供元:ナマケモノテック」として出ます。
- 新しいセッションを作り、入力欄に `/mi` と入力します。`ai-headquarters:mission` と `ai-headquarters:mission-analysis` の2つが出れば、使えます。
- AI司令部を開いた画面では、名前の下に「開発者不明」と出ることがあります。一覧の「提供元:ナマケモノテック」とは違いますが、別のマーケットプレイスから入れた Codex(提供元:OpenAI)を開いても、同じように出ました。アプリの表示によるもので、AI司令部の設定の誤りではないと考えています。

**入る範囲**

デスクトップアプリで入れると、入れる範囲を選ぶ項目は出ず、ユーザー全体(このパソコンのすべてのプロジェクト)に入ります。すべてのプロジェクトで Hooks が動きます(上の「利用者全体(`--scope user`)に入れた場合に起きること」)。

- **プロジェクト単位で入れたいとき**:デスクトップアプリではなく、上の「端末で入れる場合」の手順で入れます。1人で使うなら `--scope local`、git で共有してチームで使うなら `--scope project` にします。
- **特定のプロジェクトで止めたいとき**:そのプロジェクトの `.claude/settings.local.json` に、次のように書きます。ほかの設定がすでにあるときは、その中に `"enabledPlugins"` を足します。公式の文書によると、プロジェクトのローカルの設定は、ユーザー全体の設定より優先されます。止めたフォルダのセッションでは、`/mi` と入力しても、AI司令部のスキルが出ません。ほかのプロジェクトのセッションでは出ます。こうして、止まったことを確かめられます。

```json
{
  "enabledPlugins": {
    "ai-headquarters@ai-headquarters": false
  }
}
```

**そのほかの入れ方**:端末で入れたプラグインは、同じパソコンのデスクトップアプリのセッションでも使えます(端末とデスクトップアプリは同じ設定ファイルを読むため)。

**使えないセッション**:クラウドのセッションと WSL のセッションでは、プラグインを使えません(公式の文書)。

**Windows で、Node.js が見つからないと言われたとき**:デスクトップアプリは、PowerShell のプロファイルを読みません。Node.js を公式のインストーラーか `winget` で入れていれば、この問題は起きません。PowerShell のプロファイルで PATH を足して Node.js を使えるようにしている場合は、Windows の環境変数(ユーザーまたはシステム)の PATH に Node.js の場所を足し、デスクトップアプリを開き直してください。

出典(いずれも Anthropic の公式の文書):

- [Desktop application](https://code.claude.com/docs/en/desktop)(「Install plugins」の節と、Windows の PATH の注意)

### 更新のしかた

AI司令部の手直しは、版(`.claude-plugin/plugin.json` の `version`)を上げて公開します。すでに入れている場合、手直しは自動では届きません。公式の文書によると、外部のマーケットプレイスは、初めは自動更新が無効だからです。次の手順で、手で更新してください。

**デスクトップアプリ**(Windows のデスクトップアプリの日本語の画面で確かめた手順です)

1. 左のメニューの「プラグイン」を開きます。
2. 右上の「追加」の ▼ を押し、「マーケットプレイスを管理」を選びます。
3. `ai-headquarters` の行の「…」を押し、「アップデートを確認」を選びます。行の「最終更新」の日時が新しくなり、画面の右下に「マーケットプレイスを更新しました。」と出ます。
4. 「完了」で閉じます。左のメニューの「プラグイン」の画面で、「マイプラグイン」の右の「すべて表示」を押し、「マイプラグイン」の画面を開きます。その中の「その他のプラグイン」にある AI司令部を開きます。開いた画面の右上には「追加済み」と「更新」があります。新しい版が無いときは、「更新」が薄い色で押せません。手順3のあとは、「更新」が押せるようになっています。「更新」を押し、画面の右下に「0.3.0 から 0.4.0 に更新しました。」のような知らせが出れば、更新できています。そのあと、「更新」はまた薄い色に戻ります。
5. 新しいセッションを開いて使います。作戦の途中で更新したときは、下の「0.5.0 までの作戦記録が残っているとき」も読んでください。

**「アップデートによりローカルの変更が上書きされます」と出たとき**:手順4で「更新」を押すと、この確認が出ることがあります。本文は「2 個のファイルがローカルで変更されており、この更新により上書きされます。」で、`.in_use\16072`、`.in_use\25528` のようなファイルが並び、「キャンセル」と「強制的にアップデート」があります。このとき、プラグインのファイルは書き換えていませんでした。私たちの検証では、ほかのセッションで作戦を動かしていないことを確かめてから「強制的にアップデート」を押し、問題なく更新できました。

**入れたあとに AI司令部を探すとき**:左のメニューの「プラグイン」の検索欄に `ai-headquarters` と入力し、「すべての結果を表示」を押すと、「マイプラグイン」の中に出ます。「AI司令部」と日本語で入力したときは、候補に出ません。また、入れる前は、追加したマーケットプレイスのプラグインは、検索欄では出ません。

手順3をしないと、手順4の「更新」は押せません。アプリが新しい版を知らないためです。また、「マーケットプレイスを管理」の「削除」は押さないでください。画面の説明のとおり、マーケットプレイスを削除すると、そこから入れたプラグインもアンインストールされます。

**端末**:対象のプロジェクトの最上位で、次の2つを実行します。1つ目でマーケットプレイスの写しを新しくし、2つ目でプラグインを更新します。2つ目の `--scope` は、入れたときの範囲に合わせます。終わったら、Claude Code を起動し直します。

```text
claude plugin marketplace update ai-headquarters
claude plugin update ai-headquarters@ai-headquarters --scope project
```

デスクトップアプリで入れた場合は、ユーザー全体に入っているので `--scope user` にします。(端末での更新は、まだ確かめていません。)

### 取り除き方

- **デスクトップアプリ**:左のメニューの「プラグイン」の画面で、AI司令部の行の右の「…」を押し、「削除」を選びます(「アンインストール」ではありません)。「AI司令部を削除しますか?」「Claude はこれを使用しなくなります。後で再度追加できます。」という確認が出て、「キャンセル」と「削除」があります。「削除」を押すと、画面の右下に「AI司令部が削除されました。」と出ます。このとき、マーケットプレイスは消えず、「マーケットプレイスを管理」の一覧に `ai-headquarters` が残ります。
- **端末**:対象のプロジェクトの最上位で、次を実行します。`--scope` は、入れたときの範囲に合わせます(更新のときと同じです)。この手順は、まだ確かめていません。

```text
claude plugin uninstall ai-headquarters@ai-headquarters --scope project
```

取り除いても、作戦記録や設定を置いた `.ai-headquarters/` フォルダは、プロジェクトに残ります。要らなければ、自分で消してください。

### 0.5.0 までの作戦記録が残っているとき

0.6.0 の Hooks は、0.5.0 までの形の作戦記録(「### 時程」「### 目標の決心」「### 計画の決心」「## 計画」のどれかの見出しがあるもの)の承認を受け継ぎません。その作戦では、unit の起動が止まり、「承認」も記録されず、セッションの開始のときに、移し方が案内されます。

途中の作戦は、新しい雛形に書き直すより、次の形で移すことを勧めます。書き直すより安く、確かです。

1. 古い作戦記録の「## 結果」の最初の行(「未完了」の行)を、ここまでの結果と「残りは次の作戦に移す」に書き換えて、作戦を閉じます。
2. 残りの仕事を、次の番号の作戦記録として、新しい雛形(見出し9つ)で立てます。新しい作戦記録の「## 企図」には、古い作戦記録を経過として指す1行(例:「経過: OP-002(0.5.0 の形の記録)」)だけを置き、古い経過は写しません。
3. 新しい作戦の目標と方針が、ふつうの作戦と同じく、目標の決心と計画の決心で示されるので、それぞれ「承認」と入力します。

幕僚長に「OP-002 を区切りで閉じて、残りを新しい作戦として立ててください」と頼めば、この形で進みます。古い記録の `.ai-headquarters/state/approval.json` は、もう使いません。残っていても害はありません(`.ai-headquarters/state/` の中は Claude には消せないので、消すときは、あなたが消してください)。

## 6. 作業対象のプロジェクトに作られるもの

どれも、簡易か完全の作戦で、初めて必要になったときに作ります。実行だけの作業では作りません。

| 場所 | 中身 |
| --- | --- |
| `.ai-headquarters/operations/` | 作戦記録(`OP-001.md` のような、作戦ごとのファイル)。保存期間は定めず、削除はあなたが行います |
| `.ai-headquarters/estimates.md` | 作戦ごとの実測(日付、程度、起動の回数、作業の時間、使用量、見込みとの差)。次の作戦の見込みに使います |
| `.ai-headquarters/config.json` | 設定ファイル。あなたが手で編集します。無くても既定値で動きます |
| `.ai-headquarters/state/` | Hooks が使う状態(承認の記録と指紋(approvals.jsonl)、時計の記録(clock.jsonl)、起動の記録(launches.jsonl)、画面に出した知らせ(notices.jsonl)、unit に許したファイル、unit の実行中の記録) |

**git で管理するか**は、あなたが決めます。プラグインは `.gitignore` を書き換えません。作戦記録と実測は、残すと後から経緯を追えます。設定ファイルは、プロジェクトの決まりなので、管理して共有するのが自然です。状態は、セッションごとの一時的な記録なので、管理しないほうが無難です(`.ai-headquarters/state/` を `.gitignore` に書きます)。

## 7. 設定ファイル

`.ai-headquarters/config.json` で、保護するパス、inspector に許すコマンド、役ごとのモデル、知らせの線を調整します。例は、GitHub のリポジトリの `templates/config.json` にあります。

```json
{
  "protect": {
    "add": ["private/**"],
    "exclude": ["test/fixtures/dummy.pem"]
  },
  "inspector": {
    "testCommands": ["python -m pytest"],
    "allowedOptions": ["-q"]
  },
  "models": {
    "unit": "opus",
    "inspector": "opus"
  },
  "notice": {
    "launches": 12,
    "minutes": 60
  }
}
```

| 項目 | 意味 |
| --- | --- |
| `protect.add` | 保護パスに足すもの(書き方は第4章) |
| `protect.exclude` | 既定の保護パスから外すもの(設定ファイル、状態ファイル、作戦記録は外せません) |
| `inspector.testCommands` | inspector に許すテストコマンドの追加 |
| `inspector.allowedOptions` | inspector のテストコマンドに許す、`-` で始まるオプション |
| `models` | 役(`intel`、`plans`、`unit`、`inspector`)ごとのモデルの名前。書かない役は、エージェントの定義の値(intel は haiku、plans は opus、unit と inspector は sonnet)のままです。あなたが作戦の中で指定したものが、設定ファイルより先です |
| `notice.launches`、`notice.minutes` | 画面に知らせを出す線(作戦ごとの起動の回数と、作業の時間の分)。0 か数でない値にすると、その線は知らせません |

**`testCommands` に、`make` のような汎用の実行コマンドを書かないでください。** テストコマンドは「前置き」として照合し、その後ろの語は通します。`make test` と書くと、inspector が `make test install` のように、任意のターゲットを動かせてしまいます。`python -m pytest` のように、後ろに続く語がテストの絞り込みにしかならないものだけを書いてください。

`models` を書くと、セッション開始時の案内に、その中身が1行足されます。メインセッションは、起動のたびに、そのモデルを指定します。

設定ファイルは、あなたが自分で、メモ帳などのテキストエディタで開いて編集してください(Hooks は、Claude による書き込みを止めます)。`.ai-headquarters` のようにドットで始まるフォルダは、Mac の Finder では見えません。Finder で `Command + Shift + .` を押すと、表示されます。

## 8. 全体の CLAUDE.md との衝突

あなたの全体の CLAUDE.md(`~/.claude/CLAUDE.md`)の方針と、衝突することがあります。たとえば「作業は常にサブエージェントに任せる」と書いていると、「実行だけではサブエージェントを使わない」という進め方とぶつかります。Claude Code では、全体とプロジェクトの CLAUDE.md がぶつかったとき、どちらが優先されるかは決まっていません。本製品は CLAUDE.md に依存しませんが、衝突すると、小さな仕事でも重くなることがあります。

対処は、効き目の確かな順に、次の3つです。

1. **全体の CLAUDE.md に、例外を書き足す。** 「AI司令部を入れたプロジェクトでは、その進め方に従う」と書きます。最も確実です。
2. **プロジェクトの CLAUDE.md に、同じ趣旨を書く。** 優先は保証されません。
3. **プロジェクトの `.claude/settings.local.json` の `claudeMdExcludes` で、全体の CLAUDE.md を、そのプロジェクトでだけ読み込まないようにする。** 全体の CLAUDE.md のほかの規則も、そのプロジェクトでは効かなくなります。

   ```json
   {
     "claudeMdExcludes": ["**/.claude/CLAUDE.md"]
   }
   ```

   書き方の例です。全体の CLAUDE.md を除外できるかは、公式の説明に明記がなく、実機で確かめる途中です。プロジェクト自身の `.claude/CLAUDE.md` も巻き込むため、そのまま使わず、自分の環境の絶対パス(例:`<ホームフォルダ>/.claude/CLAUDE.md`)に直してください。

## 9. Agent Teams を使わないでください

Agent Teams(実験機能)の仲間のセッションは、Hooks からはサブエージェントに見えるため、確認ではなく拒否で止まり、作業が進まないことがあります。本製品は Agent Teams を使いません。有効にしている場合は、AI司令部を使うときだけ無効にしてください。

## 10. 限界

### 統制(Hooks)の限界

- **Hooks は安全柵であり、セキュリティの仕組みではありません。** 完全なシェルの解析はしないので、すり抜けは残ります。
- 破壊的なコマンドと、外に出す操作は、禁止リスト方式です。リストに無い道具と書き方、スクリプトの中からの実行は止まりません。1つのファイルの削除も一覧に入りません(Claude Code の権限の確認に任せます)。
- シェルのコマンドの文字列で保護パスを照合する方式は、完全ではありません。変数の展開、`eval` の中の組み立て、シンボリックリンク、8.3 形式の短い名前は解決しません。
- 行き先の分からない `cd` の後は、パスの末尾の形で照合するため、`state/` や `config.json` という名前の普通のファイルを巻き込むことがあります。保護パスの名前と `2>&1` のような書き方が同じコマンドにあると、読み取りでも書き込みと見なして止めることがあります。
- 親のフォルダを対象にした操作の検出が、外れる書き方が残ります(`tar -x -C .claude`、`unzip -d .claude`、`cp -t .claude`、`ln -s`、変数を通した指定など)。
- unit の範囲の照合は、Edit・Write だけにかかります。シェルでの書き込みは範囲の外でも止まりません。unit と inspector は、止められたら別の手段を試さないと決められていますが、これは取り決めで補っているものです。
- 他のプラグインの `PermissionRequest` の Hooks が、メインセッションへの確認に自動で答えてしまう場合があります。
- 保護パス(`.claude/` など)への書き込みでは、Claude Code 自身の確認が出て、Hooks の理由文は表示されないことがあります(実機で観測)。
- bypassPermissions では確認の画面が出ないため、Hooks は確認の代わりに拒否を返します。保護対象のパスを含む読み取りだけのコマンド(`ls .claude` など)も止まります。
- プラグインと MCP のコマンドの照合は、`claude` を直接呼ぶ形だけです。~/.claude/ の下の設定やスキルを直接書き換えることも、プロジェクトの外なので照合しません。
- 作戦中に幕僚長(メインセッション)が成果物を直接書くことは、Hooks では止めません。決まりで守らせています(止めると、作戦記録の更新や、作戦の外の普段の作業まで止まるためです)。
- `.claude/skills/`、`.claude/agents/`、`.mcp.json` への書き込みの守りは、AI司令部の4体だけにかけています。役の名前(agent_type)が無いサブエージェントは、4体以外として扱い、止めません。
- unit の起動の知らせ(SubagentStart)が届かないとき、最初の2分を読むだけで過ごす unit では、実行中の記録に切り替わる前に予約が無効になり、2体目の unit を起動できることがあります。読み取りは Hooks を通らないので、30分のあいだ読むだけの unit では、実行中の記録が無効になることがあります。
- 起動の回数は、起動の知らせで数えます。設定の線は、知らせるだけで止めません。
- 決心事項と処置事項の仕分けは、決まりで守らせています。幕僚長が、伺うべきものを処置事項に入れても、Hooks は止めません。一覧を読み、おかしければ番号で直してください。

### 承認の限界

- UserPromptSubmit の入力に、発言の出どころを見分ける欄がありません。別のセッションからのメッセージなどで、メッセージ全体がちょうど「承認」なら、承認として記録されることがあります。
- 作戦記録ができる前(前の作戦が閉じているときを含む)に「承認」と入力しても、記録されません。メインセッションが作戦記録を作ってから、もう一度「承認」と入力してください。
- 承認の引き継ぎは、作戦記録への「引き継ぎ待ち: 」「受け継ぎの申し出: 」の書き込みで働きます。書き込みはメインセッションが行うので、あなたがセッションを替えると伝えずに替えたときは、「承認」が1回要ります。
- メインセッションが作戦記録の「目標の決心: 」の行を偽って埋めれば(「省略」と書くなど)、目標の決心を飛ばせます。これは Hooks では防げず、決まりで守らせています。省かれたときは、報告に書かれた理由を読み、おかしければ「承認」と入力せずに、直す点を書いてください。
- 指紋は、「目標」か「方針」の節を、誤字の直しのように小さく書き換えても変わり、承認が外れます。
- 指紋を照らすのは unit の起動だけです。物差しを書き換えて inspector だけを起動することは、止まりません。
- 承認の記録はプロジェクトに1つの作戦(最新の作戦記録)にかかるので、2つのセッションが、同じプロジェクトで別々の作戦を同時に進めることはできません。

### 監督と見込みの限界

- 1回の命令の中で起きた誤りは、その命令が終わるまで分かりません。動いている unit の途中の様子は、メインセッションには見えないためです。
- 監督の確認と、Hooks の数字と配分の照らし合わせは、決まりで守らせています。メインセッションが確かめずに次の任務を起動しても、Hooks は止めません。
- 幕僚は、今の時刻と使用量の枠の残りを、確かには知りません。期限や枠を守りたいときは、依頼に残りを書いてください(「5時間の枠の残りは60%」など)。見込みは、実測が溜まるまでは目安です。
- 役ごとのモデルは、メインセッションが起動のたびに指定することで守らせています。指定を忘れると、エージェントの定義の値で動きます。
- 進め方の程度の推奨は、モデルの判断に頼ります。規模判定は、モデルの判断に頼ります。3ファイル以上の変更を「実行だけ」と判断することがあります。最初の3行の見込みを見て、違えば程度を書いて答えてください。

### 型と報告の限界

- 報告の型が守られているかは、Hooks では確かめません。決まりで守らせています。
- 命令書の【変更してよいファイル】に、名前に `,`、`、`、` - `、`:` を含むパスや、名前の最後が括弧で終わるパスは書けません(別のパスとして読まれます)。書かずに、未解決として上げる決まりです。
- エージェントが型どおりに書くかは、実機で測って調整する途中です。

### 環境の限界

- **`claude -p` やバックグラウンドで使うと、サブエージェントの `npm test` などのコマンドが、権限の確認を出せずに拒否されます。** 対話の画面では、確認が出ます。`-p` で使うときは、プロジェクトの `.claude/settings.json` に、テストのコマンドを許可として足してください。書き方の例です(公式の権限の説明で確かめてください)。

  ```json
  {
    "permissions": {
      "allow": ["Bash(npm test)", "Bash(npm test *)", "PowerShell(npm test)", "PowerShell(npm test *)"]
    }
  }
  ```

  Bash と PowerShell の許可は別々です。両方を書いてください。止められたサブエージェントは、もう片方のシェルで試さず、「未解決」として報告します。

- auto モードでは、unit が危ない操作を自分で断ることが多く、そのため Hooks が止める場面は少なくなります。
- クラウドのセッションと WSL のセッションでは、プラグインを使えないため、AI司令部は使えません(公式の文書。第5章の「デスクトップアプリだけを使っている場合」)。
- Windows に Git for Windows が入っていない環境では、Bash ツールが使えず、PowerShell ツールが使われます。Hooks は両方にかけています。
- 待ち時間:ツールを呼ぶたびに、Node.js を起動します。1回あたり約100ミリ秒で、そのほとんどが Node.js の起動です。Read、Grep、Glob は Hooks を通りません。

**まだ確かめていないこと**

## 12. コスト

すべて `claude -p` で、メインは sonnet、4体も sonnet で測りました(0.6.0、2026-11-26)。1回ずつの測定で、実行ごとにぶれがあります。目安です。費用は、決心の入力ごとに続けた会話の、最後の回の累計です。セッションを替えたときは、セッションごとの最後の累計を足しました。

- 実行だけ(README の誤字を1つ直す。サブエージェントなし):0.10 USD。
- 実行だけ(関数に引数を1つ足し、テストを足す):0.10 USD。同じ課題を AI司令部なしで流すと 0.08 USD で、約1.2倍です。
- 簡易(レシートの金額を「¥1,234」の形にし、整形の関数とテストを足し、README の例を直す。6ファイル):0.67 USD(入力3回。unit 1回、inspector 1回)。同じ課題の単独は 0.16 USD(0.5.0 で測った値)で、約4倍です。費用の約7割は、メインセッションの文脈の読み直しと書き込みです。
- 簡易で、途中でセッションを替えた作戦(割引を金額でも指定できるようにし、レシートに割引の行を出す。4ファイル):0.65 USD(2つのセッションの合計。起動2回。替えたための「承認」の入れ直しは0回)。
- 簡易で、作戦の前からあるファイルの削除を含む作戦(3つの手順):0.39 USD(起動2回)。
- 簡易で、満たせない完了条件を入れた作戦(起動の前に見つけて伺い、完了条件を改めた):0.63 USD(起動2回)。
- 簡易で、20の場面の試験を足す作戦:0.54 USD(起動2回)。

完全の程度(案を比べる作戦)は、0.6.0 ではまだ測っていません。目安は、起動5〜8回で、単独の8〜11倍です。

目安として、マルチエージェントは万能ではありません。公開された研究では、各手順が次の手順の前提を変える作業で、性能が下がり、成功1件あたりのトークンが大きく増えた例があります。小さな仕事を単独で片付ける進め方の程度は、そのためです。
